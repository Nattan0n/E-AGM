# E-AGM e2e bot (Playwright + pytest)

บอทที่เปิดเบราว์เซอร์จริงแล้วกดแทนคนตาม flow ใน `E-AGM_All_Flows_By_Role.drawio`
ค่าเริ่มต้นยิงที่ mockup บน Vercel (https://e-agm-one.vercel.app, `NEXT_PUBLIC_MOCK=1`)
แต่ละเทสต์เปิด browser context ใหม่ ข้อมูล mock จึงเริ่มจากชุดตัวอย่างเดิมทุกครั้ง
และทุกเทสต์รัน 2 รอบ: จอมือถือ (390×844) กับเดสก์ท็อป (1366×860)

## วิธีง่ายสุด: ดับเบิลคลิก `run_tests.bat`

เปิดหน้าต่างเมนู → ติดตั้งสิ่งที่ขาดให้เอง (ครั้งแรกใช้เน็ต) → เลือกโหมด 1–5 → รันจบแล้วเปิดรายงาน `reports/report.html` ในเบราว์เซอร์
(ต้องมี Python ในเครื่องและติ๊ก "Add python.exe to PATH" ตอนติดตั้ง)

## ติดตั้ง (ครั้งแรก, ถ้ารันเองผ่าน command line)

```bash
pip install -r e2e/requirements.txt
playwright install chromium
```

## รัน

```bash
cd e2e
pytest                                  # ทั้งหมด (~10 นาที)
pytest -m holder                        # เฉพาะผู้ถือหุ้น (-m staff / -m admin)
pytest -k "vote and desktop"            # เลือกตามชื่อเทสต์ / ขนาดจอ
pytest --headed --slowmo 400 -k vote    # เปิดหน้าจอให้ดูบอทกด
pytest --base-url http://localhost:3000 # ยิงเครื่องตัวเอง (npm run dev)
```

เทสต์ที่พังจะมี screenshot และ trace อยู่ใน `e2e/test-results/`
เปิด trace ดูทีละขั้นได้ด้วย `playwright show-trace test-results/<ชื่อเทสต์>/trace.zip`

## ไฟล์

| ไฟล์ | ครอบคลุม |
|---|---|
| `test_holder_login.py` | หน้า 2–4: เข้าด้วยเลขบัตร + OTP, PDPA ครั้งแรก, ไม่ยอมรับ PDPA, ลงทะเบียนแล้วข้าม PDPA, โหมดเจ้าหน้าที่ลงแทน → สลับเป็นลงเอง, เลขบัตรผิด / Onsite แล้ว / OTP ผิด, หน้าที่ต้อง login |
| `test_holder_vote.py` | หน้า 5: ลงคะแนน + popup ยืนยัน, แก้ไม่ได้, วาระที่ยังไม่เปิด / วาระรับทราบ, ใบยืนยัน, ผลมติยังไม่เผยแพร่, ออกจากระบบ, กดยกเลิกใน popup |
| `test_holder_request.py` | หน้า 1: ขอ User 3 กรณี (มีช่องทางแล้ว / ไม่มีช่องทาง / ไม่พบชื่อ + แนบเอกสาร), ตรวจข้อมูลไม่ครบ, ไฟล์ผิดประเภท, OTP ผิด |
| `test_staff.py` | หน้า 6–12: login + สิทธิ์ (staff เข้า admin ไม่ได้, viewer อ่านอย่างเดียว), ค้นหา, ลงทะเบียน person / proxy (ตรวจชื่อผู้รับมอบ + จำนวนหุ้น), ลงซ้ำไม่ได้, ยกเลิกลงทะเบียน, Convert ออนไลน์ → Onsite, รับเข้าห้อง + ลงคะแนนแทน, กลุ่ม, มาสาย, ตัดสิทธิ์ / คืนสิทธิ์ (รวมกรณีลงคะแนนไปแล้ว + วาระปิดแล้ว), ลงคะแนนแทน (ปกติ / เขียนทับ / แบ่งคะแนน / ล้างคะแนน / ไม่มีสิทธิ์ / วาระยังไม่เปิด), หน้าสรุปผล / roll-call / พิมพ์บัตร |
| `test_admin.py` | หน้า 13–16: เพิ่ม / แก้ / ลบวาระ, วาระที่เริ่มแล้วแก้ไม่ได้, สร้างผู้ใช้ (รหัสผ่านสั้นไม่ผ่าน), เปิด/ปิดห้องประชุม, เปิดโหวต → ปิดโหวต (ต้องติ๊กรับทราบ, เปิดซ้ำไม่ได้), ยกเลิกการปิด, เกณฑ์องค์ประชุม, เผยแพร่ผลมติ, ปิดประชุม → ทุกหน้าเป็นอ่านอย่างเดียว, ทุกหน้า admin เปิดได้ไม่มี error |
| `holder_pages.py`, `console_pages.py` | ตัวช่วยกดแต่ละหน้า (เปลี่ยน UI แก้ที่นี่ที่เดียว) |
| `mock_data.py` | เลขบัตรตัวอย่างของ mock (OTP = 123456) · Staff/Admin: รหัสผ่านอะไรก็ได้, ชื่อผู้ใช้ขึ้นต้น `admin` = admin, `viewer` = viewer, อื่น ๆ = staff |

ยังไม่ครอบคลุม: เลือกบัญชีเมื่อเลขบัตรเดียวมีหลายบัญชี (mock ไม่มีข้อมูลแบบนี้), ผลมติที่เผยแพร่แล้วฝั่งผู้ถือหุ้น,
นำเข้า CSV / export ไฟล์, การล็อกเมื่อกรอกรหัสผิด (mock รับทุกรหัส), และ flow ข้ามบทบาท (admin เปิดวาระ → ผู้ถือหุ้นเห็น)
ซึ่ง mock แยกข้อมูลต่อแท็บ ต้องทดสอบกับ backend จริง
